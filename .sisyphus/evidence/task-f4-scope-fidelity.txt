SECTION 1: USER INTENT ANALYSIS
################################################################################

ORIGINAL PROBLEM (from interview/draft):
  1. Browser page opens in a SEPARATE window — user wants it INSIDE the desktop app
  2. User must manually type LMS login credentials every session — wants save/load
  3. (Phase 3 — NOT this plan) Eventually roll Chrome extension into desktop app

INTENDED SOLUTION (from plan):
  - Replace detached browser window with embedded Tauri webview inside main window
  - Add collapsible sidebar for maximum browser screen real estate
  - Implement SQLite-backed credential storage for 4 LMS sites
  - Auto-detect login pages and auto-fill saved credentials (no auto-submit)
  - Credential management UI in Settings page

ACTUAL IMPLEMENTATION (from code review):
  - lib.rs: 10 embedded webview commands (create, navigate, back, forward, reload,
    set_bounds, hide, show, get_url, destroy) + inject_autofill command
  - browser.ts: All 10 wrapper functions + injectAutofill + event listeners +
    GRADING_SITE_PRESETS (4 sites)
  - Browser.svelte: Full URL bar with back/forward/refresh, collapsible presets
    panel, webview placeholder area, auto-fill on page load, saved URLs, toast
    notifications for auto-fill
  - App.svelte: Sidebar collapse (auto on browser, manual toggle), webview
    visibility management (hide on page switch/modal, show on return), animated
    webview bounds recalculation, window resize handling
  - db.ts: SiteCredential interface + 4 CRUD functions (get, getByUrl, save, delete)
  - lib.rs migration 5: site_credentials table
  - autofill.ts: LMS_LOGIN_SELECTORS for 4 sites, generateAutoFillScript() with
    retry logic & React/SPA compatibility, matchCredentialsToUrl()
  - Settings.svelte: Full credential management section with add/edit/delete,
    password masking with toggle, URL pattern presets, notes field
  - app.css: Sidebar CSS variables (expanded/collapsed widths, transition)
  - Cargo.toml: unstable feature flag enabled
  - tauri.conf.json: Window size 1280x900
  - capabilities/default.json: Multi-webview permissions added
  - vitest.config.ts + 3 test files (autofill.test.ts, browser.test.ts, db.test.ts)

INTENT MATCH: ✅ Aligned

EXPLANATION:
  The implementation directly solves both stated user pain points:
  (1) The browser now renders inside the main app window via embedded Tauri webview
      instead of opening a separate WebviewWindow. Sidebar auto-collapses to
      maximize browser real estate.
  (2) Credentials are stored in SQLite and auto-filled when navigating to matching
      LMS login pages. The user can manage credentials in Settings.
  Phase 3 (extension merge) is correctly excluded.
