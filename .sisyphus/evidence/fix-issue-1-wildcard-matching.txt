# Issue #1 Fix: % Wildcard Pattern Matching

**Date**: 2026-02-17 16:59
**Issue**: `%` wildcard in url_pattern breaks auto-fill - JS `includes()` doesn't treat `%` as wildcard
**Severity**: Medium (auto-fill silently fails for users who use preset buttons)
**Status**: ✅ FIXED

---

## Problem Description

From Task F3 verification report:

**Root Cause**:
- Settings UI (Settings.svelte:826) instructs users: "Use % as a wildcard"
- Preset buttons (Settings.svelte:833) append `%` to URLs: `credentialForm.url_pattern = preset.url + '%'`
- BUT: autofill.ts:198 used JavaScript `includes()` which treats `%` as a literal character

**Example Failure**:
```typescript
// Pattern: "https://www.myopenmath.com/%"
// URL: "https://www.myopenmath.com/assess2/?cid=12345"
// includes() checks if URL contains literal "%"
// Result: FALSE (no match, auto-fill fails)
```

**Impact**:
- Users who click preset buttons get patterns like "https://canvas.instructure.com/%"
- Auto-fill never triggers because `%` is treated literally
- Feature appears broken for preset-generated patterns

---

## Solution Implemented

**Approach**: Convert SQL-style `%` wildcards to proper regex pattern matching

### Changes Made

**File**: `ogre-desktop/src/lib/autofill.ts`

**Added**:
1. `wildcardToRegex()` helper function (lines 187-196)
   - Escapes regex special characters (`.+?^${}()|[]\\`)
   - Converts `%` to `.*` (match any characters)
   - Returns case-insensitive anchored regex

2. Enhanced `matchCredentialsToUrl()` (lines 198-222)
   - Detects if pattern contains `%`
   - If yes: Use regex-based wildcard matching
   - If no: Fall back to original substring matching
   - Maintains backward compatibility

**Code**:
```typescript
function wildcardToRegex(pattern: string): RegExp {
  // Escape special regex characters except %
  const escaped = pattern.replace(/[.+?^${}()|[\]\\]/g, '\\$&');
  // Convert % to .* (match any characters)
  const regexPattern = escaped.replace(/%/g, '.*');
  // Match entire string (anchored)
  return new RegExp(`^${regexPattern}$`, 'i');
}

export function matchCredentialsToUrl(
  url: string,
  credentials: SiteCredential[],
): SiteCredential | null {
  if (!url || !credentials || credentials.length === 0) {
    return null;
  }

  const normalizedUrl = url.toLowerCase();

  for (const cred of credentials) {
    const pattern = cred.url_pattern.toLowerCase();
    
    // If pattern contains %, treat as wildcard pattern
    if (pattern.includes('%')) {
      const regex = wildcardToRegex(pattern);
      if (regex.test(normalizedUrl)) {
        return cred;
      }
    } else {
      // No wildcards - use simple substring matching
      if (normalizedUrl.includes(pattern)) {
        return cred;
      }
    }
  }

  return null;
}
```

## Edge Cases Handled

1. **Special regex characters**: `.`, `+`, `?`, `^`, `$`, `{}`, `()`, `|`, `[]`, `\`
   - All escaped properly before regex conversion
   - URL like `example.com/path?query=value` matches literally

2. **Case insensitivity**: 
   - Both pattern and URL converted to lowercase before matching
   - Works with any case combination

3. **Empty/null inputs**:
   - Existing defensive checks still apply
   - Returns `null` for invalid inputs

4. **Multiple wildcards**:
   - Pattern like `https://%.example.com/%/test/%` works correctly
   - Each `%` converts to `.*` independently

5. **Anchored matching**:
   - Regex uses `^...$` anchors
   - Prevents partial URL matches
   - `canvas.instructure.com/%` won't match `notcanvas.instructure.com/`

## Backward Compatibility

**Guaranteed**:
- Patterns WITHOUT `%` use original substring matching
- Existing credentials (no wildcards) work identically
- No migration needed for existing database records
- Users can mix wildcard and non-wildcard patterns

**Example**:
```typescript
// These patterns all work:
"myopenmath.com"                          // Substring match
"https://www.myopenmath.com"              // Substring match
"https://www.myopenmath.com/%"            // Wildcard match
"https://%.myopenmath.com/%"              // Multiple wildcards
```
