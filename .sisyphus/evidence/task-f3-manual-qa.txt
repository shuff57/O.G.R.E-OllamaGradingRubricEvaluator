7. Navigating to saved LMS login page auto-fills username/password
----------------------------------------------------------------------
Status: ISSUE FOUND (Medium)

Execution Path:
  Page loads in webview -> lib.rs:215-218 on_page_load fires
  -> emits 'browser-page-loaded' with URL
  -> Browser.svelte:105-108: listenBrowserPageLoaded callback
  -> Browser.svelte:107: tryAutofill(url)
  -> Browser.svelte:44-55: tryAutofill():
    -> getSiteCredentials() returns ALL credentials from DB
    -> matchCredentialsToUrl(url, credentials) from autofill.ts
    -> autofill.ts:187-204: Loops credentials, checks url.includes(cred.url_pattern)
    -> If match found: injectAutofill(match.username, match.password)
    -> browser.ts:107-110: generateAutoFillScript() -> invoke('inject_autofill')
    -> lib.rs:347-353: wv.eval(&script) injects the JS into webview
    -> autofill.ts:67-172: Injected script finds LMS login form, fills fields

Evidence:
  - autofill.ts:23-48: LMS_LOGIN_SELECTORS for 4 platforms
  - autofill.ts:67-172: Script with retry logic (3 attempts, exponential backoff)
  - autofill.ts:99-113: Uses native setter + dispatches input/change events

ISSUE: **URL pattern matching mismatch between DB and JS**
  The Settings UI (Settings.svelte:826) instructs users to use % as wildcard:
    "Use % as a wildcard. Example: https://canvas.instructure.com/%"
  The preset buttons (Settings.svelte:833) append '%' to URLs:
    credentialForm.url_pattern = preset.url + '%'
  
  BUT: autofill.ts:198 uses JavaScript includes():
    normalizedUrl.includes(cred.url_pattern.toLowerCase())
  
  If url_pattern = "https://www.myopenmath.com/%" (as preset suggests),
  includes() checks if URL literally contains "https://www.myopenmath.com/%"
  This will NEVER match because URLs don't contain literal '%' characters.

  The SQL LIKE approach in db.ts:302 (getSiteCredentialsByUrl) would work
  with % wildcards, but Browser.svelte uses matchCredentialsToUrl (JS) instead.

  HOWEVER: If user manually types "myopenmath.com" as url_pattern (without
  the trailing %), includes() WILL match. So the feature works for simple
  domain-only patterns but breaks for the preset-suggested patterns with %.

  SEVERITY: Medium — auto-fill silently fails for users who use preset buttons.

Scenario: Both App.svelte and Browser.svelte try to set webview bounds

Expected: One authoritative source of bounds truth

  - Browser.svelte:58-83 updateWebviewBounds() reads ACTUAL DOM:
    sidebar.getBoundingClientRect().width, navBar height, presets panel height
  - App.svelte calls recalculateWebviewBounds on: resize, modal close
  - Browser.svelte calls updateWebviewBounds on: creation, presets toggle

Status: PARTIAL (Design concern)
  Two different calculation methods for the same thing.
  App.svelte IGNORES the presets panel entirely (uses hardcoded 50px URL bar).
  Browser.svelte accounts for presets panel height.
  
  After window resize: App.svelte's recalculateWebviewBounds fires.
  It uses URL_BAR_HEIGHT=50 and ignores presets panel.
  If presets panel is visible, webview will overlap it.
  
  FIX: Either:
  a) Have App.svelte delegate to Browser.svelte for bounds calculation
  b) Have Browser.svelte listen for resize and handle all bounds updates
  c) Use a shared utility with DOM-based calculation
