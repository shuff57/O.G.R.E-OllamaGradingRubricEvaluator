## 2026-03-28
- `findFuzzyMatch` now returns `{ element, strategyIndex }` so downstream fuzzy-match explanations can report the actual strategy used instead of assuming text match.
- Call sites that consume fuzzy matches must destructure the returned element before reusing the selector.
- Strategy indices remain stable by order: text=0, id/class=1, aria-label=2, tag position=3.
- `tripleClickAction` should use native CDP mouse events, not a synthetic DOM click, when triple-click selection is needed.
- For triple-click text selection, send 3 press/release pairs and increment `clickCount` from 1 to 3.
- `navigateAction` must register `Page.loadEventFired` listener BEFORE sending `Page.navigate` to avoid a race where the load fires before the listener is in place.
- Use `Promise.race([loadPromise, timeoutPromise])` for CDP wait-for-event patterns; clean up both the listener AND the timer on every exit path (success, timeout, error).
- `Page.enable` must be called before any `Page.*` event listener will fire — do it unconditionally at the start of navigateAction.
- `Page.navigate` CDP response may carry `errorText` (e.g. `net::ERR_NAME_NOT_RESOLVED`) even when the send itself resolves — check this field and return failure immediately without waiting for the load event.
- When mocking `cdp` in vitest, include `on: vi.fn()` and `off: vi.fn()` in the mock object — tests that register CDP event listeners will fail silently otherwise and the load event will never resolve.
- The timeout path for navigate should resolve with `{ success: true, warning: '...' }` — never reject, never hang — so agent loops don't get stuck on slow pages.
- `ActionResult` now has an optional `warning?: string` field for non-fatal advisory messages (e.g. load timeout).
- Bug #2 (isVisible below-fold): Remove only the viewport-position checks (`rect.top > viewHeight`, `rect.bottom < 0`) from `isVisible()`; keep display:none, visibility:hidden, opacity:0, and zero-size checks intact. This ensures all DOM elements reachable by scrolling are included.
- After removing viewport checks, compute `inViewport` in the extraction loop using `var inViewport = rect.top >= 0 && rect.bottom <= viewHeight && ...` (ES5, `var` only). Compute viewport dims (`viewWidth`/`viewHeight`) once OUTSIDE the element loop for efficiency.
- `inViewport` must be set on the element object inside `INTERACTIVE_DOM_SCRIPT` and surfaced through the `InteractiveElement` type as `inViewport?: boolean`.
- In `formatDomForPrompt` (TypeScript, outside the inline script), append `[offscreen]` to the parts array when `el.inViewport === false`. Use strict equality — `undefined` and `true` should NOT add the indicator.
- Bug #3 (AX tree replacement): The `dom = axTree` replacement caused the LLM to generate role-based locators (e.g., `role=button[name="Submit"]`) that CDP actions cannot use — CDP only accepts CSS selectors.
- Fix: always keep the interactive DOM (CSS selectors) FIRST; when AX tree has >20 nodes AND is non-empty, APPEND it as `## Page Structure (Accessibility Tree)` section after `## Interactive Elements`.
- Token budget for the merge: 8000 tokens ≈ 32000 chars (4 chars/token). If the combined string exceeds this, truncate the AX tree — never truncate the DOM.
- Edge case: if DOM alone already exceeds the 32000-char budget, return just the DOM without appending any AX section.
- System prompt rules 3 and 8 must explicitly say: use CSS selectors from Interactive Elements for all actions; AX tree is context/structure only, never use role=... as action selectors.
- When updating an existing test that tested the old (wrong) behavior, update it to test the new (correct) behavior rather than deleting it — preserves test count and test intent.
- `mergeDomWithAxTree` is exported from agent-loop.ts so it can be unit-tested directly without needing the full agent loop mock infrastructure.
- `tripleClickAction` needs best-effort fallbacks after the CDP mouse sequence: `.select()` for input/textarea and `createRange`/`getSelection` for contenteditable, because the mouse events alone are not enough for all editable elements.
- When testing `tripleClickAction`, assert the fallback `Runtime.evaluate` calls happen after the six mouse events, not just that the actions succeed.
